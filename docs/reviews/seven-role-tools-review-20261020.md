## 修复结果

| 发现 | 影响与修复 | 回归证据 |
| --- | --- | --- |
| P1：旧会话工具声明覆盖当前常驻集合 | pi 恢复历史声明后，可能缺少新加入的 `record_fact` 或 `tool_search`。绑定扩展后，通过 SDK 公开接口合并当前允许且已注册的常驻工具，保留已发现工具；不恢复已撤销工具，不重放调用。 | `internal-discovery.test.ts`：修复前新增的两例均失败，修复后通过；包含搜索、实际写回、后续读取和再次恢复。 |
| P2：Planner 看到的 Worker 能力清单偏离装配策略 | 原清单只根据 MCP 判断是否存在搜索，漏掉内部按需搜索，并可能保留新会话已合并的旧名。现在复用 `prepareToolLoading`、策略、提示词及显式绑定 Skill，保留自定义旧名兼容。 | Worker 能力清单与真实装配预览逐项一致；无需 MCP 即可搜索内部工具。 |
| P3：运行配置重复记录工具名 | 执行工具与允许列表都含 `bash` 时，诊断的常驻列表重复。装配策略按名称去重，运行清单与预览一致。 | 七类真实入口逐项比较常驻与按需集合。 |
| P2：未绑定任务的 Pentest 预览多报自定义执行工具 | 运行入口原本不装配这些工具，预览却会显示。预览现在遵循同一绑定任务条件。没有扩大实际权限。 | 插入仅绑定 Pentest 的合成自定义命令，验证独立会话的预览与实际集合一致。 |
| P2：交互终端关闭后仍可被发现 | 原执行守卫会拒绝调用，但搜索仍可能激活 `shell_open`，让模型反复调用失败工具。搜索现检查角色启用状态及 `interactive_shell`，执行守卫继续保留。 | 真实 Worker 会话运行中撤销终端；搜索不返回它，强制调用被拒绝，随后 `record_fact` 仍成功写回。 |

变更未修改 pi 源码、模型循环、意图完成规则、并发配额或用户工具绑定。

## Worker 写回与 Planner 去重

- 新增实际 Worker 回归：意图的执行工具白名单只有 `read` 时，业务写回与工具搜索仍正常。事实在最终答复前已经可读，最终答复后原生循环结束。
- 黑板回归验证事实及漏洞增量发布、稳定调用 ID 幂等、事务回滚、陈旧执行器拒绝写入，以及后续失败不丢已发布结果。
- 工作身份回归验证 12 个并发等价提案只创建一条意图、不同文字的相同结构化工作去重、终态意图不被普通派单重建，以及有效新证据才能显式重试。
- 生命周期回归验证 Planner 读取变化后下发后续意图直至自然结束；暂停恢复、进程强杀后事实与已提交操作不重复。
- MCP 回归覆盖 stdio、HTTP、SSE、服务不可用时内部搜索仍可用、发现后撤销及恢复后的撤销检查。

去重有明确边界：结构化工作身份、已知旧身份和幂等调用可确定判断；仅凭一句自然语言的任意同义改写，不能承诺百分之百语义去重。未新增语义审核模型，也未以重复派单掩盖这一限制。
