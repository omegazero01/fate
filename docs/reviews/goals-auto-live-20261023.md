# Goals → Planner → Worker：真实 DeepSeek 自动任务验收

日期：2026-10-23（Asia/Shanghai）。使用独立 PostgreSQL 数据库、临时任务目录、一次性本地 HTTP 服务及真实 DeepSeek；验收脚本仅从生产数据库读取现有模型配置和角色配置，未运行既有测试目标。

## 闭环设计与验收口径

目标栏只有一个最终结果：“证明本地合成样本总和与独立核对值一致，形成有证据的核验结论。”描述包含原文操作限制、明确授权的本地资产，以及仅作背景的架构分析、接口梳理和漏洞挖掘。目标阶段实际请求不得包含背景标记。

自动任务通过真实 `/api/tasks` 创建，`execution_mode=managed`、无种子意图。Goals 初始化后，由 Planner 派发两条串行意图：A 获取本地样本并计算 `[4,7,9]` 的总和；A 写回并退出后，B 根据已发布事实中的随机 token 请求独立核对接口。随后 Planner 读取结果并用证据证明目标，宿主自然将任务置为 `done`。验收脚本不代写事实、目标证明或自动任务终态。

文件及终端检查使用另一个手动合成任务，仅验证执行工具；其结束标记由验收脚本设置，不能当作自动调度收官证据。

## 发现与修复

| 问题 | 根因与修复 | 提交 |
|---|---|---|
| `Tool asset_search not found` | Planner 每轮派单前需要读取资产摘要，而该工具被列为低频。改为常驻，并保持原有绑定和禁用校验 | `92b860c5` |
| 按需工具误调用提示不清 | 自定义系统提示词绕过 SDK 默认工具说明。补充固定加载约定，保留原生搜索；误调用仍记录为失败，同时给出精确搜索方式，不伪造成功、不自动重放工具 | `92b860c5` |
| 将 goal 用作派单依据 | 精简 Schema 弱化了 `contract.basis` 的类型限制；恢复关键说明。可读但类型错误的节点返回明确类型错误；过期或不可读节点仍返回通用错误，不泄露跨任务信息 | `7c5b4b7a` |
| 当前意图要求的 `asset_get` 未就绪 | 会话开始时，提示词、已绑定 Skill、当前意图明确引用的工具在既有许可集合内激活，其余继续延迟加载。撤销或禁用工具仍不能被恢复 | `895f98dc` |
| 旧变量目录测试仍断言 8 项 | Goals 新增独立 `Goal` 变量后应为 9 项；更新断言，并直接校验 Goals 的目标／背景两个变量 | 随验收资料提交 |

新增装配策略不会扩大角色工具集合，不修改 SDK 源码或模型／工具循环，也不将错误调用转换成隐藏的自动执行。Worker 有锚定资产时提供详情入口；无资产时不注入无用的 `asset_get` 提示。

## 工具装配的成本取舍

不再要求每个角色机械维持原来的 30% 首轮 Schema 缩减：角色明确必需的工具应当就绪，以减少无效调用和恢复请求。固定默认配置下，最终预览的原始／首轮 Schema 分别为：Planner 17,639／13,601 字节（约减 22.9%）、Main 27,130／19,432（约减 28.4%）、Worker 19,873／13,553（约减 31.8%）。

Worker 的实际意图若明确要求更多工具，首轮 Schema 会相应增加；预览返回 `context_activation` 说明任务上下文仅在运行时装配，运行记录中的 `referencedActive` 显示实际激活名称。不能用默认 Worker 的 11 个工具假装所有意图始终只有 11 个。

- `attempt-2.json`：两条意图及 9 个执行工具运行完成；捕获资产查询加载及错误 basis 类型两类调用问题，不能计为零错误通过。
- `attempt-3.json`：源码闭环、执行工具全部通过，32 次真实请求；独立复验仍继续进行。
- `final-compiled.json`：编译产物闭环及 9 个工具成功，但暴露 Planner／Worker 各一次未加载的 `asset_get`，不能计为整体通过；据此增加必需工具激活策略。
- `final-required-tools.json`：自动任务再次自然结束、无工具错误，19 次请求；旧脚本强制 Worker 搜索一个已就绪的工具而失败，故修订夹具，将真正的按需发现单列验证。

+- `tool-probes-final.json`：改用获准的资产查询工具，原生发现成功；夹具误将 `type` 写进不支持该字段的 DSL，调用被正确拒绝，不计通过。
+- `tool-probes-verified.json`：使用文档支持的 `port==80` 查询，独立发现及 9 个执行工具全部通过，13 次请求。最终汇总仅组合相同编译组件的自动任务有效部分和该独立工具用例。

目录：[完整证据](evidence/goals-auto-live-20261023/)。所有 API Key 仅从运行时配置读入内存，退出时清除隔离数据库中的模型凭据；没有将生产密钥或配置备份写入 Git。
