# Token 计量深入修复与验收（2026-10-26）

本轮修复计量数量、归属、持久化及展示，不新增货币计价，不修改 pi 模型循环、工具权限或任务调度。保留原有未提交修改及用户配置。最终版本、部署和测试数以同目录 evidence/token-meter-20261026/acceptance.json 为准。

## 统一口径

- pi 未缓存输入 + 缓存读取 + 缓存写入 = 输入总量；输入总量 + 输出 = 总 Token。推理已包含在输出时不再加一次。
- 唯一 request_id 对应一次物理 Provider 请求尝试。重试、候补、压缩、连接诊断分别计量；工具调用、用户消息和模型路由预解析不另计请求。
- 账本无业务外键，保存脱敏归属快照。清除调用明细或删除任务、会话、配置不删除累计计量；删除来源的原详情保持不可访问。
- 累计量包含已删除来源的已保存计量。缺失 usage、旧 SDK 全零占位和未知历史口径均不冒充真实零值。
- 总量、配置汇总为累计保留范围；days 控制趋势窗口，响应显式返回 total_scope=retained_all_time 和 daily_days。每日按请求时间转 Asia/Shanghai；无法核定日期的旧汇总保留累计量，单列 unassigned_time，不分配到某一天。
- unknown_usage_calls 仅统计可识别请求中用量不全的项；旧执行汇总只计入 legacy_records，不能把一条汇总当作一次未知请求。
- 有歧义的旧重叠记录通过 unverified_history 单列，不在请求上再次相加。不完整时显示“已记录用量”，缓存输入口径不完整时不显示命中率。

回执竞争曾用回归稳定复现：旧版本出现 pending_calls=1、usage_complete=false，最新终态回执已丢失。修复后每个 request_id + revision 使用独立文件和内存键，数据库按版本更新，旧版清理无法删除新版。兼容此前未带版本的回执文件。

## 入口与兼容

| 入口 | 口径 |
|---|---|
| 任务列表 tokens、任务总览、/api/exploration/tokens | 同一账本，同一任务包含其绑定会话，请求只计一次 |
| workers、sessions | Worker 按意图/执行归属；Main 按分段；Planner/Goals 保留 plan 组 |
| 旧 main | 位于 session_aliases.main，标记 is_alias；不加入规范 sessions，不参与二次加总 |
| TurnSummary | 完整回合持久计量；含失败和压缩，不依赖当前活动分页 |
| /api/tokens/usage | 全局累计、稳定配置 ID、按请求时间的北京时间趋势、完整性与未核定历史 |
| /api/tokens/daily | 可确认请求时间的日桶；未定日期的记录在全局 unassigned_time 单列 |
| /api/tokens/conversations | 会话自身用量，删除来源仅展示“已删除”；不作为全局附加项 |
| /api/llm/records | 原调用明细保持，输入改为含缓存总量并提供未缓存字段；清除明细不清账本 |

聚合的 models/profile_ids 保留实际多模型、多配置身份。多个配置时单值 profile_id/llm_profile_id 为 null，不能将全部消费归到某个配置。未记录的旧配置名称不从当前配置推测。

真实 DeepSeek 共 24 次物理请求，包含准备、纠错和连接诊断；没有访问外部测试目标。主计量样本 14 次，输入 44,611、输出 641、缓存读取 4,864，逐请求账本与原生 usage 合计一致。该批 Worker 夹具没有先显式派发，写回被归属校验拒绝；不将其当作成功写回。修正夹具、确认领取后补测 3 次（含诊断），输入 2,799、输出 179、缓存读取 1,280，实际写入 1 条合成事实，工具错误 0。其余 7 次准备和错误夹具不计业务验收通过。测试库的运行时密钥已清理，证据不含凭据或模型正文。
