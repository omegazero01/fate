# 方向级派单与结论级写回

已部署 `direction-writeback-v1-20261021`。Planner 以资产范围和有价值的方向派单，Worker 自主选择验证路径，按结论合并观察并写回实际资产、已测范围、未测部分与限制。

例如，一个“探索用户服务的身份边界”意图可以覆盖多个相关入口。多个入口共同支持一个结论时写成一条事实；独立结论才分别记录。不要求 Planner 列出每个接口、参数或请求，不新增完成协议和模型预算。

## 宿主实现

- `add_intent` 仍可只给 `summary`、`asset_ids` 和已有依据。`contract` 可仅补边界，目标和 acceptance 缺省从方向说明补齐；无需逐项验收表或强制 `work` 字段。
- 派单身份保存不可变的资产快照；后续发现资产、参数或指纹不改变原派单身份。精确重复复用旧意图，运行中的部分范围重叠返回相关意图 ID；暂停、取消和有理由重试的限制继续有效。
- `record_fact`、`report_finding` 只关联显式 `asset_ids`，不把当前意图全部资产自动视为受影响资产。所属意图、事务、执行租约、幂等重试和直接写回保持不变。
- 新增可选 `scope: { tested, not_tested?, limitations? }`。同一结论可概括多个入口。字段缺失仍保留记录，但宿主回执标明缺项，不计入明确范围的测试记录。
- `observation_type` 缺省为 `unknown`，高置信度不自动变为实测。推断、未知、无证据、无范围、无实际资产的记录不计入覆盖。
- 列表、过滤、覆盖统计和资产图使用同一投影。“有范围测试记录”不等于整个资产或方向测试完毕。旧记录和旧 tested 标记原文保留，显示“历史范围待核实”，不自动认定从未测试或已全面测试。
- Planner 增量和检索摘要携带观察类型、写回完整性及范围续读引用；不每轮重复注入完整报告。

宿主验证字段、来源、事务和状态完整性；没有新增语义判定模型，也不声称能自动证明模型每句话正确。文字不同但语义相同的方向仍需 Planner 查阅已有工作判断，精确查重不能替代这一过程。
