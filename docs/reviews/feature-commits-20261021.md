## 回滚方法

使用 `git revert` 创建反向提交，保留审计历史。先查看目标提交及后续依赖，再在隔离分支验证；不要在存在未提交业务改动的工作区直接回滚。

例如，仅撤回 Worker 中断恢复代码时：

```sh
git show --stat 13ecf688
git revert 13ecf688
```

有依赖的功能应从后向前撤回。例如撤回 Planner 上下文时，先处理后续依赖该会话与历史接口的改动，再撤回 `c084992d`；不能先删掉 `e8d63e82` 的会话支持。资料提交可以单独撤回，但相应验收脚本需要与其功能代码配套使用。

`3ad7eb73` 的审批退役和资产存储共享同一次数据库迁移，作为一组提交与回滚。Git 反向提交不会恢复已经归档、删除的数据库表和函数。回退这一组前必须停止执行器、备份当前数据库与会话，再验证反向迁移或历史备份恢复方案；恢复旧数据库还需单独处理部署后新增数据。不能仅执行 `git revert` 后直接启动旧服务。
