# Planner Token 优化方案与验收

后续真实 DeepSeek 对照及正式发布见 [2026-10-27 真实模型与发布验收](context-budget-live-release-20261027.md)。下文保留本阶段当时的验收范围。

Planner 的高消耗主要来自跨轮会话增长、重复图谱投影和过密事件唤醒。本轮优化保留 pi 的模型循环、工具配对、会话持久化与原生压缩，保留图谱、证据原文、来源引用和 Worker 增量写回。

## 基线

2026 年 10 月 27 日只读核对的 Planner 请求账本，输入包含缓存读取。按物理请求去重，不将活动用量再次相加。

| 任务 | 规划轮数 | 请求数 | 累计输入 | 未缓存输入 | 缓存读取 | 输出 | 压缩请求 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 4856 | 28 | 65 | 4,446,093 | 376,077 | 4,070,016 | 62,726 | 0 |
| 4858 | 18 | 101 | 11,293,746 | 675,634 | 10,618,112 | 71,140 | 0 |

这两组已记录请求的 usage 完整；其消耗不能等同于未缓存输入或供应商账单。4858 单次输入从 7,368 增长至 217,652。当前 258,000 窗口与 pi 默认 16,384 预留形成约 241,616 的压缩触发点，因而未触发容量压缩。4858 最后一条请求约 782 KB，工具 Schema 约 15.7 KB；继续缩短工具名称不是主要优化方向。

## 实施方案

### 一 模型摘要与上下文预算

- 修复“不限输出”配置删除请求级明确输出上限的问题。普通未指定上限的请求继续不限；摘要指定的上限仍然生效。
- 保留 pi 根据 Provider 选择的输出上限字段，例如 DeepSeek 使用 `max_tokens`；只有用户显式配置字段时才覆盖，避免平台统一改成 `max_completion_tokens`。用本地协议夹具覆盖不限输出和配置上限两种情况。
- Planner 默认采用 `planner-context-v2`，工作上下文压缩目标为 48,000 Token，近期消息保留目标为 12,000 Token，单次摘要输出上限为 2,048 Token。
- 利用 pi 原生 reserve/keepRecent 设置提前触发压缩，不改模型真实窗口，不裁剪会话数组，也不把它实现为模型请求次数限制。小窗口模型按其容量缩小工作目标。
- 48k 是触发目标而非每个 HTTP 请求的硬上限。最新工具返回、Schema 与宿主动态投影仍可能使单次输入越过该值。
- 摘要使用既有模型路由、用量审计和总请求预算；失败、取消或预算不足时保留原始会话，不把失败摘要写入历史，不自动重放工具。
- 现有 `GET/PUT /api/settings` 增量提供 `planner_context_budget_tokens` 数值字段，支持 8192–1000000；缺省为 48000，0 恢复原容量压缩。非法值返回 400。设置在下一次 Planner runner 创建时生效。运行配置接口返回实际策略，并能显示配置待生效差异；无需数据库迁移或新增工具。

### 二 图谱输入去重与按需读取

- 将同一来源任务、同一节点、同一版本的近期事实与领域变化合并，公共字段仅出现一次。
- 保留各投影独有字段；不同结论保留带来源栏目的冲突投影。版本缺失、版本不同、来源任务不同均不合并。
- 保留事件 ID、确认边界、分页及恢复标记。再次收到相同投影不重复注入，失败回合仍恢复原交付内容。
- 固定宿主约定提示先根据变化摘要确定读取范围，批量读取相关引用及必要字段，不遍历所有详情。用户自定义提示词不被覆盖。

### 三 规划通知合并

- Worker 运行时，资产变化、漏洞发布及来源漏洞通知按最早未确认事件合并，等待窗口 30 秒；正常轮询与资源排队另计。
- 首次规划、Worker 结束、用户控制、约束变化和到期心跳继续触发；没有运行中 Worker 时不额外等待。
- 等待期间不确认或删除事件。原始数据库时间用于恢复，进程重启或新事件到来不会重新开始计时。
- 扫描整个未确认队列判断紧急事件，再分页取交付记录，防止排在第 51 条以后的 Worker 结束通知被资产事件遮挡。
- 漏洞已在事务中发布持久事件，宿主不再额外把它转成一条紧急 `control_changed`。漏洞与事实依旧即时可读，延后的是模型规划。

## 验收方法与结果

仅使用隔离数据库、原生 pi、确定性模型与本地 HTTP 协议夹具；本轮不调用真实 DeepSeek、不访问外部测试目标。

已通过专项：原会话恢复、原生压缩失败保留、工具不重放、证据原文续读、未读范围与节点版本、图谱来源隔离、相同意图去重、事件合并、紧急事件越过分页、即时写回及自动任务自然结束。原先要求漏洞发布后立刻规划的测试改为验证“即时可读、批次唤醒、Worker 结束后补位”，完整断言仍覆盖自然结束。

固定合成历史、相同工具集合，生成历史后恢复 10 轮，统计原生模型上下文序列化字节；包含初始请求和额外摘要请求：

## 最终 REVIEW

- 压缩和恢复：压缩点、工具配对及 JSONL 历史仍由 pi 管理；失败摘要不提交，恢复不会重放已执行工具。原始证据仍可分页读取。
- 数据完整性：去重键包含来源、节点和版本；不同版本和冲突字段保留。通知等待期间不确认事件，Worker 结束和用户控制不会被前 50 条普通通知遮挡。
- 计量与配置：摘要仍进入原请求审计和预算；普通请求“不限输出”保持原行为。48k 是工作集压缩目标，不是模型调用次数限制。回退设置在下一次 Planner 会话装配生效。
- 运行行为：Worker 的资产、事实和漏洞写回保持即时；改变的是低优先级事件触发模型规划的频率。意图去重、Worker 并发、角色权限及任务终态机制未改。
- 限制：本轮没有真实模型质量、供应商用量或缓存收益结论。合成夹具不能证明所有长任务都节省 89.7%，也不能证明压缩后的自然语言摘要完全无损；需要在合成任务上追加真实模型对照后评估。

## 发布与回退

本轮完成代码、隔离验收及编译，暂不重启生产服务或修改现有任务状态。发布时先核对活动执行器，沿用已有安全退出流程切换独立后端发布产物；暂停任务保持暂停，不为发布擅自暂停新任务。

后续步骤按以下顺序进行：先在本地合成自动任务上做真实模型新旧策略对照，确认目标完成、事实可读与无重复派单；再在执行器安全退出后发布；最后观察自然任务的上下文增长和规划频率。当前交付状态为“代码与确定性回归完成、真实模型成本验收及生产发布待执行”。

上线后以同等工作量比较普通请求与摘要请求的合计 Token、未缓存输入、输出、缓存命中率、任务完成率和重复派单次数。压缩可能打断缓存前缀，不能仅以输入变小判断实际费用下降。

上下文策略可通过上述高级设置 0 回退。源码按摘要上限、上下文装配、事件合并分别提交，支持逐项 Git revert；回退不删除 JSONL 历史、图节点、用量账本或事件记录。
