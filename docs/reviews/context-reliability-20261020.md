# 上下文与执行恢复可靠性实施及验收

## 实施方案

以当前工作区为基线，保留既有修改、原始会话、自定义提示词和运行中的任务。pi 继续负责模型/工具循环、持久会话和压缩；本轮只补宿主状态和原生工具适配。

1. **操作记录与恢复**：Worker 的命令、HTTP、自定义工具、MCP 和文件修改在实际执行前保存操作记录，返回后保存结果。以意图、工具、规范化参数和执行代次标识操作；同一调用重试、恢复后的相同操作复用已保存结果。未返回的操作在恢复时标记 `uncertain`，不猜测成功或自动重放；读取、事实和漏洞写回继续可用。提供任务内只读查询和暂停且执行器退出后的人工核对接口，核对保留审计。旧记录不推断执行状态。
2. **上下文保留与缺口**：增加有界、可续读的宿主清单，列出当前意图、事实依据版本、已保存成果、未读区间及未知操作。稳定规则留在固定前缀；每轮只追加短清单，原文继续通过现有检索读取。已撤销/变化的引用标为缺口，不注入旧正文；摘要不能代替事实或读取证明。
3. **工作身份与去重**：对结构化工作身份、URL 和资产别名做保守规范化，利用同一任务中的实际资产关系匹配；维持协议、端口、路径大小写、请求方法、参数和登录身份的区别。新派单返回匹配原因及冲突/重复引用；旧轻量意图保持兼容，不用自由文本相似度直接判定语义等价。
4. **验收与提交**：每批确定性模型和隔离 PostgreSQL 回归；覆盖强杀、未知窗口、取消、重复调用、版本变化、分页、冷图及来源任务、并发去重。最终执行完整服务端测试、前后端类型检查和构建，复查修改与历史内容隔离，并按功能提交。仅本地合成资料，外部目标请求为零。

## 验收边界

- 已提交操作不重放；未知操作阻止盲目重放，不宣称任意第三方系统的 exactly-once。
- 有界上下文必须给出未返回数量及续读方式，不能把截断或搜索为空当作不存在。
- 去重只自动合并可确定等价的工作；语义近似方向保留可解释依据，不静默丢弃。
- 本轮不自动恢复暂停任务，不改用户预算、并发、授权或自定义提示词。

### 数据与接口契约

- 增量创建 `worker_operation_epochs`、`worker_operations`、`worker_operation_resolutions`，不改写旧图谱、正文或用户提示词。
- 工具开始前记 `running`，真实返回后记 `returned`；失联恢复标记 `uncertain`。执行代次和意图归属失效时禁止旧执行器确认结果。
- 同一次调用重复处理复用原返回；跨执行恢复后的相同工具及规范化参数复用保存结果，并明确标注“没有重新验证外部当前状态”。同一活跃执行中的新调用仍可再次观察，不能把轮询等正常行为全部禁止。
- 交互终端仍在运行时视为未结算；进程退出后的旧终端句柄不会作为可继续使用的成功结果返回。
- `GET /api/tasks/:id/operations`：沿用平台鉴权；支持 `intent_id`、`operation_id`、`cursor`、`limit`。Worker 的工具入口只能读当前意图，其他任务及来源任务不会因此获得操作记录权限。
- `POST /api/tasks/:id/operations/:operationID/resolve`：仅人工接口，接收 `outcome=confirmed|retry_allowed` 及 `reason`。要求任务已暂停、执行租约和槽位均退出；冲突返回 409。保存核对审计，不自动恢复任务。Agent 没有此工具。
- `context_search` 新增 `operations`、`needs`；`context_get` 新增 `operation:ID`，沿用完整 JSON、分字段和分页读取。旧参数保持兼容。
- 工作身份标识为 v2；`dedup.strength` 明确区分 `structured` 与 `legacy_text`，重复返回已有意图 ID，活跃部分重叠要求重新评估。
