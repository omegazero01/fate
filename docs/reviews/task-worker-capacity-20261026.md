# Worker 按任务并发修复验收（2026-10-26）

## 结论与行为

`workers` 表示每个任务独立的 Worker 并发上限。原实现统计所有任务的占位，导致其他任务满额时 #4851 无法领取；任务设置页的原说明却已经是“每个任务”，存在实现与界面冲突。

- 自动领取只扣减所属任务名额，数据库事务与执行租约仍保证跨实例不超限、不重复归属。
- 手动恢复使用同一份本任务配额；满额返回 409，不改变暂停意图。重复恢复不增加占位。
- 已提交但尚未退出的 Worker 继续占位，实际释放后才可补位。旧规划、待领取占位不算执行并发。
- 调低配置不打断现有 Worker，下一次领取或手动恢复按新上限检查。
- 事务内读取配置复用事务连接，避免持锁时再次借连接导致连接池饥饿。
- 调度响应增加 `limit_scope: task`；`available` 改为本任务空闲数。保留 `global_active` 为诊断总数，不再将它除以本任务上限。
- 界面显示“本任务执行／上限”“本任务空闲”，配置说明同步。任务准入并发是另一项设置，没有改动。

生产 `workers=10` 未修改。本次未操作生产任务的状态、目标、意图或暂停配置。
