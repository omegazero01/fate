使用当前运行配置中的官方 DeepSeek profile `453`（`deepseek-flash`），凭据只在运行时读取。没有修改生产默认模型。最终复验复制了生产的角色提示词、运行预算，以及内置工具绑定、启用状态和自定义说明。

隔离数据库：`fate_seven_live_62729`。以下 ID 仅属于该隔离库，不是生产任务 ID。使用部署后的 dist、真实 HTTP API、原生 pi 和真实模型，目标为进程内 `127.0.0.1` 合成服务。隔离库关闭不需要的 bash/write/edit/shell 能力，Worker 配额设为 1；MCP 与自定义外部执行服务不参与本轮真实模型场景。

每个任务均要求 A 读取随机样本和资产详情并写事实；A 完成后 Planner 依据该事实派 B，以样本 token 独立复核结果，再证明目标并自然结束。资产标题包含运行时随机值，必须实际按需读取，不能靠启动摘要猜测。

逐项结果：

- 三个任务均 `done`，全部六条意图 `done`，目标 `met`。没有人工写入终态；完成后观察窗口内没有新增模型请求，Worker 名额全部释放。
- 领取延迟 107–1252 ms。六条事实在 Worker 最终退出前 2167–5171 ms 已可从探索图读取，验证了及时写回。
- 每个任务只有两个方向。第二意图的父节点分别为第一条事实 4、10、16，且都在第一 Worker 完成后创建。
- 对已完成方向再提交相同结构化身份，均返回原意图 ID、`submitted=0`，没有新增意图。
- 最终三组只有六次合成 HTTP 请求，sample/confirm 各一次；暂停恢复不重发成功请求、不重写事实。流量表所有目标 host 都是 loopback。
- 事实和意图的资产锚点保留。没有创建 finding，不把合成资料伪造成真实漏洞。
- `asset_get` 首轮未激活，通过原生 tool_search 后激活并实际调用；写回工具始终常驻。

### 没有隐藏的失败

最终运行有三次工具拒绝：一次约束原文摘录不完整、一次向已退出 Worker 纠偏、一次派单漏填 contract.objective。宿主未放行错误调用；模型修正/读取新状态后继续完成，没有丢事实或重复执行。不能把本轮写成“所有模型调用参数均一次正确”。

较早的旧会话探针虽然任务自然完成，但模型未实际调用 asset_get，发现工具的断言失败。该轮未计通过；后续增强合成资料，使随机资产标题成为验收所需信息，再重跑通过。失败记录保留于 `legacy-first.json`。
