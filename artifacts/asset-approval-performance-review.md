# 资产审批、入库与页面性能复核

> 历史设计记录：资产审批与动作拦截已于 2026-10-19 移除。当前行为以 `apps/server/README.md` 和源码为准；本文审批相关内容不再适用。

## 结论与边界

此次覆盖资产登记/模板/授权判断、图谱可见性、审批展示以及活动流到前端的关键调用链。修复内容在本地，未部署远端、未修改业务数据库，不表示远端的全部卡顿均已消除。

对用户提供的活动流执行了一次限时 5 秒的只读请求：HTTP 200，连接约 4ms，首字节约 819ms，收到约 85KB 数据后由测量端主动结束。没有复现 12 秒首响应。SSE 的请求总时长会随长连接增长，不能视作页面加载耗时；还应区分首字节、历史回放完成及浏览器渲染耗时。报告不保存登录令牌。

## 已修复

| 优先级 | 已确认问题 | 修改 |
| --- | --- | --- |
| P1 | 广播队列满时静默丢事件，后续更大的 SSE 游标会越过丢失事件 | 关闭落后的订阅，让客户端从最后已收到的游标重连补回；取消订阅保持幂等 |
| P1 | SSE 首次 flush 等待数据库回放；回放查询不随浏览器断开取消 | 立即发送无游标的连接注释；回放使用请求上下文及每批 10 秒上限；写失败停止发送 |
| P1 | 前端历史回放每条事件都复制会话状态、合并并排序 | 按 50ms 收集并按会话分组，每组只合并一次；保留分页、历史阅读与内存裁剪行为 |
| P2 | 图谱页面逐节点递归查询祖先、逐节点查询授权，共享资产反复校验 | 一次批量递归查询，按资产去重后批量读取来源/当前任务授权；摘要仍保留专门校验 |
| P2 | 用户资产授权依据逐记录 INSERT，相同主机重复登记 | 主机去重后通过 UNNEST 一次写入；继续在原事务内执行 |
| P2 | schema 与模板 SQL 分别定义同一个授权函数，旧实现每次启动又被覆盖 | 保留一份统一实现，去掉重复旧版本 |
| P2 | Agent 登记的副作用更新忽略错误、父资产读取未检查迭代错误 | 返回数据库错误，不静默继续；过滤无关父记录并去掉未使用列 |
| P2 | 封禁详情查询未沿用请求取消上下文 | 接入已有的请求级查询封装 |
| P3 | 无调用的审批别名、已提前返回类型的后续不可达判断、未使用字段 | 删除 AuthorizeTaskAsset/AuthorizeTaskAssets 别名，简化不可达条件和冗余读取 |

## 仍建议继续处理

1. **资产写入的全局串行锁。** `withCompanyScopeMutation` 仍在锁内完成资产写入及关联任务模板协调。批量发现时仍可能拉长其他写请求的等待。建议先记录锁等待/事务持续时间，再按批次去重受影响任务，仅协调一次。不能直接去掉锁：它承担企业范围和授权并发一致性。
2. **审批封禁详情和意图资产的重复读取。** 存在封禁的任务仍逐项补充部分详情；`IntentAssets` 的同一资产也可能在多个意图上重复执行有效授权。建议按授权所属任务及资产去重批量读取，再映射回 DTO，避免使用长期授权缓存导致撤回不即时生效。
3. **页面轮询分散。** 多个组件各自刷新任务、会话、意图和模型信息。建议统一相同请求的缓存与在途去重，并对不可见页面降频；不要将审计流和资产控制变成延迟数分钟生效的缓存。
4. **上线后的分段测量。** 记录连接池等待、SQL 耗时、SSE 回放条数/时长以及浏览器长任务。当前只读 HTTP 测量不能证明远端是否已运行本地最新版本，也无法定位远端 PostgreSQL 的具体执行计划。

保留：非法输入拦截、三种审批模板、用户封禁/撤回/删除墓碑、来源任务只读、服务接口继承、执行前与写回校验。它们不是可随意删除的重复代码。
